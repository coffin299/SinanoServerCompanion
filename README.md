# SinanoServerCompanion

サーバーへの参加年数に応じて「n年生」ロールを自動で付け替える、身内向けの Discord Bot です。

## 機能

- **新規加入時の自動付与**: 「新規加入時必ず付けるロール」と 1 年生ロールを付与します。
  メンバー審査（ルール同意）がある場合は、通過した時点で付与します。
- **学年ロールの自動更新**: 起動時と一定間隔（既定は 24 時間）ごとに、
  参加記念日を迎えたメンバーの学年ロールを付け替えます。
- **管理パネル（Components V2）**: `/学年パネル` でチャンネルに常設パネルを設置し、
  次の一括処理をボタンで実行できます。
  - 学年ロール同期 / 学年ロール一括削除
  - 加入ロール一括付与 / 加入ロール一括削除
  - 任意ロール一括操作（ロールを選んで全員に付与、または全員から削除）
  - 中止 / 表示更新・設定再読込
- **学年確認**: `/学年確認 [メンバー]` で参加日と学年を表示します。

コマンドやボタンへの応答は、確認ダイアログや拒否メッセージも含めてすべてチャンネルの全員に見えます
（エフェメラル表示は使っていません）。メンションはしません。
- **ホワイトリスト**: スラッシュコマンドとパネル操作は、
  `コマンドを使えるユーザーID` に書いたユーザーだけが使えます。
  サーバー上の権限は関係ありません。
- **カスタムステータス**: Bot のステータス文とオンライン状態を設定できます。
- **通知**（メンションは一切飛びません）
  - **お祝い通知**: 定期同期で学年が上がった人ごとに
    「🎉 祝！○○さんがn年生になりました！」を送ります。
    手動の一括操作や新規加入では送りません。
  - **入学祝い**: 新規加入者のロール付与後（メンバー審査がある場合は通過時）に、
    「🌸 祝！○○さんが（サーバー名）に入学しました！ようこそ！」をお祝い通知チャンネルへ送ります。
  - 進級祝い・入学祝いは、LLM に毎回違う文面で書かせることもできます
    （[お祝いを LLM で書く](#お祝いを-llm-で書く)）。
  - **システムログ**: 設定再読込、パネル設置、定期同期の結果を記録します。
    定期同期は、変更か失敗があったときだけ結果を送ります。
  - **一括操作ログ**: 手動の一括操作（実行者・結果・「n人がa年生になりました！」）と、
    その中止を記録します。

- **メンション応答（LLM）**: Bot をメンションすると、LLM が返信します（既定は NVIDIA NIM）。
  - Bot の返信にメンション付きで返信すると、返信チェーンを遡って会話の流れを踏まえて答えます。
  - 必要に応じて DuckDuckGo でウェブ検索し、その結果をもとに答えます。
  - ホワイトリストとは関係なく、サーバーの誰でも使えます。
  - `サーバーID` 以外のサーバーでも、Bot が参加していれば応答します（DM には応答しません）。
    ロールの付け替え・入学祝い・進級祝い・管理パネルは、`サーバーID` のサーバーでだけ動きます。
    応答するチャンネルや、1 人あたりの利用間隔を設定できます。

ロールは Bot 側では作りません。既存のロール ID を `config.yaml` に書いてください。

## メンション応答（LLM）

1. [build.nvidia.com](https://build.nvidia.com) で API キー（`nvapi-...`）を発行します。
2. `config.yaml` の `LLM` セクションで `有効: true` にし、`APIキー` を書きます。
3. 起動（またはパネルの「表示更新 / 設定再読込」）後、Bot をメンションして話しかけます。

- メンション直後に `待機中メッセージ`（既定は「💭 考え中…」）を返信し、
  応答ができたらそのメッセージを書き換えます。失敗したときもエラー文に書き換えるので、
  待機中のまま残ることはありません。
- 本文なしでメンションすると「はい、何か御用でしょうか？」と返します（API は呼びません）。
- 応答が 2000 文字を超える場合は、複数のメッセージに分けて送ります。
- 推論モデルが出力する `<think>…</think>` は取り除きます。
- `Web検索: true` のとき、モデルが必要と判断した場合だけ検索します（1 回の応答で最大 3 回）。
  ツール呼び出しに対応していないモデルでは、自動で検索なしに切り替えて応答します。
- **モデルのフォールバック**: `モデル` を複数書くと上から順に試し、
  エラー・タイムアウト・廃止のときは次のモデルに切り替えます。
  廃止（HTTP 404 / 410）と判定したモデルは、設定を再読込するまで飛ばすので、
  気付かないうちにモデルが消えていても応答が止まりません（ログに警告が出ます）。
  1 つのモデルでの再試行は 1 回だけなので、最悪の待ち時間は
  「`タイムアウト(秒)` × 2 × モデル数」程度になります。
- OpenAI 互換 API なら、`APIのURL` と `モデル` を変えて NIM 以外（ローカルの LLM など）でも使えます。
- **MESSAGE CONTENT INTENT は不要です**。Discord の仕様で、Bot へのメンションを含む発言と
  Bot 自身の発言は本文を読めるためです。そのため、返信チェーンの途中に
  メンションなしの発言（返信時に「@オン」を外したもの）があると、その発言の本文は履歴に入りません。

### お祝いを LLM で書く

`LLM` セクションで `有効: true` と `お祝いもLLMで書く: true` にすると、
進級祝い・入学祝いを `キャラクター設定` の口調で LLM が毎回書きます。

- LLM には `進級祝いの指示` / `入学祝いの指示` に表示名などを差し込んだ文と、
  定型文（`お祝いメッセージ` / `入学祝いメッセージ`）を参考として渡します。
- メンション応答と同じ `キャラクター設定` を土台にするので、お祝いもキャラクターの口調で書かれます。
  定型文は内容の参考としてだけ渡し、口調は真似しないよう指示しています。
  名前・一人称・口調・語尾・口癖などを具体的に書くほど反映されやすくなります。
- 生成に失敗した場合や空の応答だった場合は、定型文をそのまま送ります。お祝いが抜けることはありません。
- `お祝いメッセージ` / `入学祝いメッセージ` を空 `""` にしてお祝い自体を無効にしている場合は、LLM でも送りません。
- 指示を空 `""` にすると、その祝いだけ定型文のままになります。
- 1 回の定期同期で LLM が書くのは 10 人までです（超えた分は定型文、API の使い過ぎ防止）。
- お祝い文ではウェブ検索を使いません。

## 学年の数え方

- 参加日（`joined_at`）から満何年経ったかで決まります。参加 1 年未満なら 1 年生、
  1 年以上 2 年未満なら 2 年生です。
- 記念日は `タイムゾーン` の暦日で判定します（既定は `Asia/Tokyo`）。
- 設定したロール数より長く在籍している人は、最後のロールのままになります。
- Discord の仕様上、一度退出して再参加すると参加日がリセットされ、1 年生からになります。

## お祝い通知の条件

- 学年ロールを持っていた人が、定期同期でより上の学年ロールに変わったときだけ送ります。
- 学年ロールを持っていなかった人に初めて付けた場合は送りません。
  そのため、導入直後の初回同期で全員分のお祝いが流れることはありません。
- 複数人が同時に進級した場合は、2000 文字以内に収まるように 1 通へまとめて送ります。

## レート制限への配慮

- 1 人あたりの付け外しは、1 回の API 呼び出しにまとめています。
- 変更が不要な人には API を呼びません。
- 変更した人ごとに `API操作間隔(秒)` だけ待ちます（既定は 1 秒）。
- パネルの進捗表示は `進捗更新間隔(秒)` ごとにまとめて更新します。
- 一括処理は同時に 1 つしか実行できません。手動処理の実行中は定期同期を見送ります。
- discord.py が 429（レート制限）を受けた場合も、自動で待ってから再試行します。

## セットアップ

### 1. Discord Developer Portal

1. Bot を作成してトークンを発行します。
2. **Bot → Privileged Gateway Intents → SERVER MEMBERS INTENT** を有効にします。
3. Discord の 設定 → 詳細設定 で開発者モードを有効にし、
   操作を許可するユーザーの ID をコピーしておきます。
4. OAuth2 の URL Generator で、スコープ `bot` と `applications.commands`、
   権限「ロールの管理」「チャンネルを見る」「メッセージを送信」「メッセージ履歴を読む」を選んで招待します
   （「メッセージ履歴を読む」は、パネルの進捗を 15 分以上更新し続けるために使います）。
5. サーバー設定 → ロール で、**Bot のロールを付け外し対象のロールより上**に移動します。

### 2. 起動

`start.bat` をダブルクリックします。

- 初回は `.venv` の作成と依存パッケージのインストールを行います（Python 3.10 以上が必要です）。
- 初回起動時は `config.example.yaml` を `config.yaml` にコピーして終了し、
  メモ帳で開きます。編集してから `start.bat` をもう一度実行すると、`config.yaml` を読み込んで起動します。
  コピー処理は `main.py` が行うので、`python main.py` で直接起動した場合も同じです
  （このときメモ帳は開きません）。
- `requirements.txt` が変わったときだけ、依存パッケージを入れ直します。
- `__pycache__` は作らない設定で起動します。

## 設定（config.yaml）

トークン、動作設定、ロール設定はすべて `config.yaml` に書きます。
このファイルは `.gitignore` 済みです。

| キー | 説明 | 既定値 |
| :--- | :--- | :--- |
| `Botトークン` | Bot のトークン | （必須） |
| `サーバーID` | ロール管理・お祝い・パネルの対象サーバーの ID（LLM 応答はこれ以外のサーバーでも動く） | （必須） |
| `コマンドを使えるユーザーID` | コマンドとパネルを使えるユーザー ID のリスト | （必須） |
| `カスタムステータス` | Bot のステータス文（128 文字以内、空なら非表示） | なし |
| `オンライン状態` | `online` / `idle` / `dnd` / `invisible` | `online` |
| `お祝い通知チャンネルID` | 進級祝いと入学祝いを送るチャンネル。`0` で無効 | `0` |
| `システムログチャンネルID` | システムログを送るチャンネル。`0` で無効 | `0` |
| `一括操作ログチャンネルID` | 一括操作ログを送るチャンネル。`0` で無効 | `0` |
| `お祝いメッセージ` | 進級祝いの文。`{name}` `{grade}` `{role}` を差し込める。空 `""` で送らない | `🎉 祝！{name}さんが{grade}年生になりました！` |
| `入学祝いメッセージ` | 入学祝いの文。`{name}` `{server}` `{role}` を差し込める。空 `""` で送らない | `🌸 祝！{name}さんが{server}に入学しました！ようこそ！` |
| `タイムゾーン` | 記念日を判定するタイムゾーン | `Asia/Tokyo` |
| `Botを対象外にする` | Bot アカウントを対象から外す | `true` |
| `定期同期間隔(時間)` | 自動同期の間隔。`0` で無効 | `24` |
| `API操作間隔(秒)` | 一括処理で 1 人変更するごとの待ち時間 | `1.0` |
| `進捗更新間隔(秒)` | パネルの進捗表示を更新する間隔（2 以上） | `5` |
| `新規加入時必ず付けるロール` | `表示名: ロールID` の一覧（空でも可） | なし |
| `サーバー参加年数ごとに付けるロール` | 上から 1 年目, 2 年目, … の順に並べる | （必須） |

`LLM` セクション（メンション応答）のキーは次のとおりです。

| キー | 説明 | 既定値 |
| :--- | :--- | :--- |
| `有効` | メンション応答を有効にする | `false` |
| `APIキー` | API キー（有効時は必須） | なし |
| `APIのURL` | OpenAI 互換 API のベース URL | `https://integrate.api.nvidia.com/v1` |
| `モデル` | モデル名、またはモデル名のリスト（上から順にフォールバック）。Web 検索にはツール呼び出し対応モデルが必要 | `meta/llama-3.3-70b-instruct` |
| `キャラクター設定` | 性格・口調などの指示（システムプロンプト） | フレンドリーなアシスタント |
| `温度` | 応答のランダムさ（0〜2） | `0.7` |
| `最大トークン数` | 1 回の応答の最大トークン数 | `1024` |
| `会話履歴の件数` | 返信チェーンを遡る件数。`0` で遡らない | `10` |
| `Web検索` | DuckDuckGo でのウェブ検索を許可する | `true` |
| `検索結果の件数` | 1 回の検索で渡す結果の件数（1〜10） | `5` |
| `応答するチャンネルID` | 応答するチャンネルのリスト（他のサーバーのチャンネルも可）。空なら参加している全サーバーの全チャンネル | `[]` |
| `ユーザーごとの間隔(秒)` | 同じ人が続けて話しかけられる間隔。`0` で制限なし | `3` |
| `タイムアウト(秒)` | API の応答を待つ最大秒数（5 以上） | `60` |
| `待機中メッセージ` | メンション直後に返信する待機中の文言。空 `""` で出さない | `💭 考え中…` |
| `お祝いもLLMで書く` | 進級祝い・入学祝いを LLM で書く（失敗時は定型文） | `false` |
| `進級祝いの指示` | LLM への指示。`{name}` `{grade}` `{role}` を差し込める。空 `""` で定型文のまま | 1〜2 文のお祝いを依頼する文 |
| `入学祝いの指示` | LLM への指示。`{name}` `{server}` `{role}` を差し込める。空 `""` で定型文のまま | 1〜2 文の歓迎を依頼する文 |

```yaml
コマンドを使えるユーザーID:
  - 555555555555555555

カスタムステータス: "在校生を見守り中"
オンライン状態: online

新規加入時必ず付けるロール:
  一般生徒: 111111111111111111

サーバー参加年数ごとに付けるロール:
  一年生: 222222222222222222
  二年生: 333333333333333333
  三年生: 444444444444444444
```

- 表示名は重複できません（YAML の仕様上、後の行が前の行を上書きしてしまうため、エラーにしています）。
- 加入ロールと学年ロールに同じロールは指定できません。
- コマンド一覧には全員に表示されますが、ホワイトリスト外のユーザーが実行すると拒否されます。
  一覧からも隠したい場合は、サーバー設定 → 連携サービス でコマンドの表示対象を絞ってください。
- パネルの「表示更新 / 設定再読込」を押すと、再起動せずに設定を反映できます
  （ホワイトリスト、ステータス、`LLM` セクションも反映されます）。
  ただし、トークンとサーバー ID の変更だけは再起動が必要です。

## 構成

| パス | 役割 |
| :--- | :--- |
| `main.py` | 起動エントリポイント |
| `companion/config.py` | YAML の読み込みと検証 |
| `companion/grade.py` | 参加年数から学年を計算 |
| `companion/roles.py` | ロールの計画と適用（1 人 1 API 呼び出し） |
| `companion/actions.py` | 一括処理の定義 |
| `companion/bulk.py` | レート制限を考慮した一括実行器 |
| `companion/notify.py` | お祝い通知（LLM での文面生成を含む）とログの送信 |
| `companion/panel.py` | Components V2 の管理パネル UI |
| `companion/slash.py` | スラッシュコマンド |
| `companion/chat.py` | メンション応答（会話履歴の収集と返信） |
| `companion/llm.py` | OpenAI 互換 API の呼び出しとツール実行 |
| `companion/search.py` | DuckDuckGo のウェブ検索ツール |
| `companion/bot.py` | イベント処理と定期同期 |
| `start.bat` | `.venv` の作成と起動 |
